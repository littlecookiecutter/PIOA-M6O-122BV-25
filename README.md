## Лабораторная 2: In-Memory база данных (процедурная реализация)
Прототип базы данных, работающей в оперативной памяти. Реализован консольный интерфейс, динамические схемы таблиц, валидация типов данных.

## Лабораторная 3: ООП и тестирование
Рефакторинг СУБД в объектно-ориентированную архитектуру с применением TDD.

## Лабораторная 4: Файловая СУБД и индексация
Расширение архитектуры: добавлена поддержка файлового хранения (JSON/CSV), механизм индексации для ускорения поиска и переключение режимов хранения без перезапуска программы.

### Архитектурные решения
| Решение | Обоснование |
|---------|-------------|
| **Абстрактный класс `Database`** | Позволяет заменить способ хранения без изменения TUI. |
| **Изоляция хранилищ (`data/json/`, `data/csv/`)** | Исключает конфликт имён файлов и случайное редактирование метаданных одного формата через другой. |
| **CSV + `.meta.json`** | CSV не хранит типы и схему. Метаданные вынесены отдельно для сохранения чистоты формата и полной персистенции состояния таблицы. |
| **Инкапсуляция приватных методов** | TUI не обращается к `_load_table` или `_dir`. Все взаимодействия идут через публичный API (`get_schema`, `drop_table`). |
| **Переключение режимов в runtime** | Удобство демонстрации и тестирования. Сброс активной таблицы предотвращает обращение к несуществующим данным. |

### Реализованный функционал
- Единый интерфейс `Database` для трёх реализаций: In-Memory, JSON, CSV
- Персистентное хранение: данные сохраняются на диск и восстанавливаются при следующем запуске
- Поддержка типов: `str`, `int`, `float`, `bool`, `int_pos`, `int_neg`, `float_pos`, `float_neg`
- Автоматическая генерация уникального `id` и сохранение счётчика между сессиями
- CRUD-операции, фильтрация, сортировка по любому полю
- Механизм индексации: ускорение поиска по выбранному полю, автообновление индексов при изменении данных
- Валидация типов и семантических ограничений на уровне ядра
- Пользовательские исключения для чёткой обработки ошибок
- Консольный интерфейс с возможностью смены режима хранения без перезапуска
- Автоматизированные тесты (`unittest`), общее покрытие проекта ≥80%

### Запуск приложения
Требуется Python 3.9+
```bash
python -m src.db
```
При запуске предлагается выбрать режим хранения. В главном меню пункт `11` позволяет сменить режим в любой момент.

### Запуск тестов и проверка покрытия
Требуется: `pytest`, `pytest-cov`
```bash
# Установка зависимостей (если не установлены)
pip install pytest pytest-cov

# Запуск тестов с отчётом по покрытию ВСЕГО проекта (backend + tui)
python -m pytest tests/ --cov=src --cov-report=term-missing
```
Цель: общее покрытие `TOTAL` не менее 80%. Тесты покрывают бизнес-логику, файловые операции, обработку ошибок, индексы и консольный интерфейс.
